# Instrument method library and agent selection learning

This delivery adds bounded research mechanisms, not a profitable Master or
Champion Council. Sources, library versions and agent skill have separate owners.

## Inventory and input

The operating curriculum separates **taught base knowledge** from **earned
agent practice**. It covers all 26 existing instruments: six tactics, nine
market lenses, seven risk tools, two management/sizing tools and two model/router
tools. Each pinned lesson contains sourced operating steps, exact implementation
and smoothing conventions, legitimate alternatives, required observations,
WAIT conditions, misuse examples, and finite executable exercises. It is not
another set of usage cards or a claim that all methods are profitable.

`php artisan trading:instrument-methods curriculum --json` reads this complete
curator-owned instruction corpus without registry/model writes. `teach` accepts
only `{ "recipe_hashes": ["<exact installed hash>"] }`: it reopens original
source/method/recipe identities and returns the relevant frozen teaching pack.
Missing or altered mapped declarations fail closed; a genuinely unrelated
custom method is explicitly unmapped. Operator exercises are synthetic
correctness evidence, not backtest profit, trained meta weights or market labels.

New eligible ordinary constructor children bind the code-owned pack into their
existing signed generation handoff **before** their own policy is sealed. Caller
teaching flags and copied packs cannot establish that handoff. Old policies and
active generations remain unchanged. The full curriculum is available; the
existing bounded selected recipe roster stays separate and is not silently
expanded to execute all 26 tools at every decision.

Practice subsequently follows the existing original policy/recipe event and
owned mature outcome chain. Library instructions are not rewritten when an
agent proposes a new contextual selection policy. A useful instruction can be
technically correct while losing money in a given context; passing a lesson
never grants Master, mentor, credit, promotion, paper or live authority.

Reviewed media are scoped honestly: creator-published rules, official technical
documentation and exchange/broker instructional text, an official webinar's
related transcript passage, and an author's trading-plan excerpts. Book resource
metadata is labelled metadata-only; no full book or inaccessible video is claimed
as reviewed. External pages remain references, never executable trusted code.

See `source-grounded-method-backtests-2026-10-14.md` for original paired results,

## Actual use and agent learning

The actual PHP request builder attaches the exact selected model policy. Python
validates it before cache and execution, then records closed-input selection,
WAIT/context reason, real target use and behavior change. Methods unreachable
from the trade lifecycle report unreached, not a fabricated successful invocation.
Ordinary receipts are in data_quality.instrument_method_learning_receipt;
native receipts belong to their exact council member. Existing immutable
screening projection reopens original products before persisting experiences.

`learn` requires run_id. `propose` requires policy_hash, next revision and bounded
max_recipes. It is observational prioritization, not profitability-based Master.
`evolve` makes a fresh, same-baseline research model from the original proposal
and experience lineage. It does not dispatch a generation or promote a council.
The original library, models, exposure history and receipts are unchanged.

`study-prepare` accepts an unused original own-policy child, exact L1/L2 recipe
hashes, an explicit physical study contract and canonical source declaration.
The server reopens its original parent/proposal facts and maps the old/learned
rules by stable recipe class. Four fresh signed own-policy carriers are created
atomically with the existing study/work registration. The original child and
parent are not rebound or replayed. The original proposal root owns a single
question allowance; changed labels/budgets cannot renew it. Identical selectors
return no_effect with no carriers or replay. Only verified policy derivation is
excluded from baseline comparison, never unknown trading/cost/risk metadata.

Closed method inputs come from an as-of feature owner, not caller/CSV fields.
Pivots are delayed until right bars close, session extrema are prefix-only and
loss state changes only after mature owned closes become observable. Fresh
accounts start with a known empty own journal; no parent performance is copied.
Generic typed operators cannot gain the method-input capability by copying its
wire marker. Missing observations/model produce explicit conservative dependency
reasons and retain their original receipt hashes.

With `services.instrument_methods.generation_learning_enabled`, only newly
constructed ordinary generations pin the configured exact recipe hashes.
An eligible unused child receives its own new policy before any parameter/run
seal. Original parent experiences yield at most one bounded frozen proposal,
recompiled for the child's actual legal vector and new data scope. Server-owned
handoff provenance is verified again on use. Exact comparative/cooperative,
native council, passport and protected abstain/adversarial seats are unchanged;
their own experiment owner must explicitly declare an intervention. A generation
marker therefore does not imply that every seat received a method. Missing parent
evidence, unsupported adapters or scopes remain typed dependencies. Neither
proposals nor this observational inheritance confer economic/causal authority.

## Closed sessions, actual quotes and price confirmations

Four append-only supplements use the existing source/method/recipe import path:
`observed-quote-firewall`, `closed-band-reentry`, `closed-ema-pullback` and
`closed-donchian-retest`. Import their source file(s),
then `method.json`, then `recipe.json`; no active model or old library revision
is rebound. Together with the calibrated-score supplement, they declare 33
method classes / 35 revisions and 43 recipes, not 33 qualified skills.

The quote rule requires actual validated closed BID/ASK availability and
`spread / simple ATR(14) < 0.10`. Its cap is a laboratory hypothesis. Invalid,
immature, future or missing quotes produce WAIT, while the physical execution
spread/commission/risk remain identical. The canonical method feature ATR is
the simple fourteen-true-range average, not an unlabeled Wilder recurrence.

The canonical quoted CSV column is `spread`. The closed feature owner also
accepts legacy `bid_ask_spread`; when both are present, both must be finite and
equal after numeric parsing. A malformed or contradictory alias cannot fall
back to the other column. Availability, original BID-close equality, ASK/BID
spread consistency and closed quote timestamps remain mandatory. A modeled
spread alone is unavailable. Source regression fixtures are explicitly
synthetic software inputs; genuine provider samples and original products stay
in private evidence storage.

A separate quality-selected December 2025 diagnostic pair preserved 512 real
quoted rows, 200 warmup rows and 312 decisions. Both original requests completed
once within unchanged 120-second caps and shared exact account, risk, modeled
costs, clock and trade ledger: nine trades and net cash -182.19. All 512 quotes
validated; all 312 evaluated decision rows and 134 method events had available
quote features. The declared trend-up/London/normal entry context never occurred,
so the selector retained BASELINE and the recipe had zero uses or changed
decisions. This establishes canonical quote-input compatibility, not observed
rule utility, independent market qualification or trading authority. No
outcome-dependent retuning, renewed attempts or historical receipt edits follow.

The band rule uses twenty-close SMA and two population standard deviations.
The previous close must be outside its own completed band; the current close
must move inward and be strictly inside its own band, in the proposed direction.
Band contact, a stationary price recaptured only by widening bands and later
confirming candles cannot satisfy the rule. This is a fresh lab confirmation
hypothesis informed by the original Bollinger documentation, not a copied
profitable strategy. It creates no direction or increased risk.

The pullback supplement uses fixed EMA20/50 (`adjust=False`, `min_periods=50`)
from closed observations, with mature values on two immediately adjacent bars.
BUY requires a prior low touching EMA20, a prior close above EMA50 but no higher
than EMA20, fast EMA above slow EMA on both bars, and a current close strictly
above EMA20 and the prior close. SELL mirrors those comparisons. Earlier EMA
history may contain gaps, but the immediate confirmation pair may not. The
[primary EMA reference](https://help.ctrader.com/indicators/built-in/trend/exponential-moving-average/)
defines the indicator and discusses lag/false signals; this exact period pair
and bounce are unqualified laboratory hypotheses.

The retest supplement excludes the breakout bar from its prior20 high/low
channel. A strict close across that channel from its previous inside-side close
arms a frozen level, not an entry. Only one of the next three contiguous closed
bars may confirm a same-direction level touch and a strict close on the breakout
side; the breakout candle itself and repeated retests cannot confirm. Equality
at the closing level waits, while an opposing close, gap or expiry cancels.
The [primary Donchian reference](https://help.ctrader.com/indicators/built-in/volatility/donchian-channel/)
defines channel extremes, not this complete delayed-retest recipe or its profit.
Both supplements use trend-up/London/normal/hour context, AND availability with
directional confirmation, and can only veto an existing candidate. Their
software tests invent no volume or market evidence and grant no order or
trading authority; missing observed data and model power remain dependencies.

Normal raw OHLC snapshots now supply absent session labels, instance IDs and
calendar version from the existing selection calendar before session extrema
are compiled. Explicit unknown session columns stay unknown. Past extrema do
not change when a future suffix is added.

Legacy construction semantics are retained rather than retroactively repaired:
the v1 band adapter is an extreme fade, its breakout retest branch does not
consume the declared two-confirmation parameter, and its spread gate reads
modeled costs rather than observed quote coverage. Testing those old adapters
must describe their actual behavior, not assert those missing capabilities.
The new band and observed-quote revisions are the corresponding explicit
executable rules. Missing observed volume/quotes and an underpowered fitted
meta model remain data/evidence dependencies, not invented skill successes.

The final compatibility check found that the native EMA strategy emits no
confidence field, while the old no-volume wrapper inserted zero and thereby
overrode the existing price-only admission fallback. Future no-volume wrappers
preserve that absence; they do not write a guessed confidence or change the
threshold. Explicit zero/low/NaN/malformed values and active-volume behavior
remain unchanged. Native full-ledger/clock parity is a software regression,
not a calibrated probability, repaired old experiment or profitable strategy.

different checks. The old26 primary rules were24 confirmation operators, one
fixed risk multiplier and one exit. Their names do not mean they generate
entries, route specialists or learned a calibrated prediction. Reopening the
old27-arm originals found policy-default entries in every treatment; most

what was actually tested and what remains unknown; registration does not turn
