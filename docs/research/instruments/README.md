# Curator instrument research journal

This is the assistant's source-grounded research, not an agent's own experience
or a list of independently profitable skills. Primary targets are scalp and
day trading. Broker demo is not connected; project replay and internal paper
are not broker execution. All market observations from 2026 onward stay
paper-only.

## Unit of work

Study one named instrument deeply enough to distinguish its actual uses. Each
instrument dossier records:

1. Reviewed source, exact chapter/page/transcript range, access date and what
   was **not** inspected. A video title is not a watched masterclass.
2. Author's method versus the curator's explicit hypotheses; data, as-of time,
   setup, confirmation, entry, invalidation, sizing, SL/TP and management.
3. Implementation fidelity and missing adapters/data. Do not silently replace
   order flow with candle shape, or exchange volume with a different measure.
4. Before-outcome question, all arms, data/calendar selection, account/costs,
   declared budget and the complete original artifact/source identities.
5. Every original outcome, including technical failure, zero activation,
   negative/neutral observations and incompatible sources.
6. Contextual know-how: measured opportunities, uncertainty, useful limitations,
   counterexamples, and the next discriminating question.

Different-month coverage is required for the current practice panels; it does
not make reused history independent. Choose dates using a recorded calendar
rule before outcomes, retain refusals, and do not keep selecting dates until
PnL looks good. Warmup and decision rows are separate. An untimed demo account
or an unfinished trade cannot supply a mature economic outcome.

## Knowledge labels

`source_rule` means a faithfully identified published rule. `hypothesis` means
an executable question, not a skill. `observed_know_how` can preserve a useful
limitation or promising result for bounded research even without qualification.
`qualified_skill` requires the separate applicable original-data/authority
process. No label here issues credit, Master status, paper/live access or an
agent's own outcome. A losing version does not refute every use of an
instrument; popularity does not prove the implementation's economic edge.

The curator library and agent policy remain separately versioned. Teaching a
curated observation is not copying it into an agent's self-earned experience.
The agent must later record its own actual consumption and result.

## Append-only events and original custody

Each dossier has `events/` records. A new event refers to the preceding
event's exact SHA256; never overwrite an earlier review, question or outcome.
Review and question bytes are frozen before original execution. After all
attempts are terminal, append a result event linking actual retained products.
README files are the current readable synthesis; event and original artifact
bytes are the historical record. A new question must declare what was already
seen and cannot call those data untouched.

The bounded offline owner reuses the existing Python replay. It is not a new
scheduler, a production hot-fix, or an unbounded search for a positive backtest.
Only a code-reviewed registered adapter can define a new question. Retained
originals, not a hand-written table, must support reported results.
