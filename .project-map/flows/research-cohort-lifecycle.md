# Cross-module flow: research cohort lifecycle

## Purpose

Move a bounded research cohort from eligible construction to a settled,
auditable outcome without collapsing data, computation, gate and paper roles.

```text
Market-data continuity
  -> Dynamic 20-seat scientific blocks and frozen controls
  -> Final constructor identity rebound to each frozen composition passport
  -> Frozen M5/H4/H1/M15 autonomous replay bundle
  -> Laravel/Python deterministic screening and replay
  -> Laravel gate/holdout settlement
  -> Paper admission and observation
  -> Settlement-watermark terminal boundary
  -> Evidence-aware completion, rejection, quarantine or archive
  -> Arbiter-owned successor + immutable autonomy receipt
```

## Modules

- `market-data`: certifies the data-continuity precondition.
- `laboratory`: owns cohort identity, lifecycle and learning provenance.
- `laravel-python-contract`: seals and attests cross-runtime computation.
- `paper-execution`: observes only candidates admitted to paper.
- `operations`: observes queue/runtime boundaries and recovery.

## Invariants

- One protected construction boundary cannot silently open duplicate active work.
- Python computes deterministic results; Laravel owns lifecycle/persistence gates.
- A missing or invalid receipt cannot become evidence of a passing gate.
- Session/venue/context and actual component activation remain attributable
  from population construction through replay settlement.
- A declared composition either validates all executable bindings before
  replay or fails technically; partial observation is reserved for valid
  organisms whose downstream nodes were not reached.
- Strategy, tactic, risk, management, instrument, dataset/MTF and execution
  identities are sealed as one authority; `consumed` requires every typed node
  receipt and a completed managed trade from that exact authority.
- XAUUSD H1 is a population/storage identity, not the ordinary replay stream;
  screening and full validation execute on M5 with frozen H4/H1/M15 context.
- Paper observation is not live authority.
- Full-validation closure requires terminal agents, no open immutable run or
  queue ownership, and a terminal learning watermark. Technical closure is a
  terminal quarantine, not a scientific pass, and does not block arbiter
  reselection of the next bounded research action.
- Repeated scheduler minutes do not imply new work; the arbiter emits another
  child only after a generation/run/queue/settlement watermark changes.
- Failed queue rows block learning admission only while their source agents
  belong to the current technical-recovery lookback or active lineage head;
  older quarantines remain append-only history and cannot starve all later
  cohorts.
- A confirmed drift after a zero-pass cohort cannot enter the `market_drift`
  constructor directly. An eligible final report first goes through the
  lifecycle-owned, non-promotional data-edge audit; otherwise it uses the
  ordinary `new_data` lane. Fresh-candle admission remains mandatory there, and
  frozen-MTF admission remains mandatory for both paths.
- Fresh-data retries remain deduplicated below the candle threshold and become
  eligible once per complete 24-H1/96-M15 candle-count window; audit/report
  disposition changes the state hash so deferred lifecycle work can resume.
- Two consecutive clean generation receipts, linked by arbiter-created
  successors, are the unattended autonomy acceptance boundary. Each source
  generation must retain verifiable provenance from its own arbiter creation
  decision; failed predecessor audits never create a clean receipt.
