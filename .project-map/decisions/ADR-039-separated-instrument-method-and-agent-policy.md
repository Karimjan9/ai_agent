# ADR-039: Separate instrument methods from agent selection learning

Date: 2026-10-13

## Context

An instrument implementation, its external-use hypothesis and the specialist's
ability to choose it are not the same skill. Updating a library cannot certify
all its consumers. One successful selector cannot certify every method.

## Decision

Preserve the existing 26-card/five-group inventory. Add append-only source,
method and recipe records, with intrinsic library snapshots. Compile bounded
runtime exports separately for an exact pre-2026 data/execution/baseline/context.
Keep agent policy revisions and original experience in separate tables. Only
original eligibility-verified run artifacts create experience; copied receipts
or caller qualification flags do not. Proposals and fresh rebased candidates
are research-only with reverified original lineage.

Use the existing ordinary/native executors and immutable learning projection,
not a second scheduler. Runtime methods can veto, reduce existing risk or request
an owned exit. Unsupported stateful semantics and construction parameter deltas
remain explicit dependencies, not silently simulated capabilities.

Freeze library and policy axes independently in a four-arm study. Exact account,
costs, risk, source clock, model identity and caps must match. Local archive
execution is diagnostic; confirmation, Master, inherited economics, council
qualification and paper admission remain separately evaluated.

## Consequences

Every card has a use contract, but registry membership is not algorithm or
profitability coverage. Additional sourced methods can be registered without
changing active versions. Automatic copyrighted caption retrieval is not
assumed; supplied permitted transcripts and bounded public documents are
references, not trusted code. All 2026 and later data remains paper-only.
The programme-key index becomes nonunique by AST while the original unique
programme key remains, allowing fresh bound research exports. Rollback refuses
duplicate semantic scopes instead of deleting research history.

Standalone fresh candidate creation alone is not autonomous canonical dispatch.
The active deployment remains protected until separately verified release,
migrations, actual loaded-worker hashes and canonical admission are complete.
