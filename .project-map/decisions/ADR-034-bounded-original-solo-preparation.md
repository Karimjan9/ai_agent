# ADR-034: Bounded original SOLO preparation

Date: 2026-10-09
Status: Accepted implementation contract; runtime acceptance separate.

## Evidence

The original typed SOLO producer reached native programme and transport sealing,
but its single atomic 33-unit request preparation took 904.5703454 seconds against
the existing 900-second owner delivery budget. Constructor deliveries fit that
budget. Whole-test duration was not treated as one delivery; the limit was not
enlarged to make the software test pass.

## Decision

Only new standalone-qualification and qualified-SOLO selection panels use staged
request-digest preparation. Legacy independent/descendant paths retain atomic
preparation. The same existing work, original scientific question, three cohorts,
programmes and data are preserved.

First seal every original definition, global plan, model and source release. Keep
cohorts research_reserved and agents draft. Each genuine fresh lease then appends
at most four ordered original request hashes to an HMAC-bound prefix checkpoint.
Every continuation rechecks original source/data/model/plan/release and the
authenticated prefix. Source or checkpoint drift blocks rather than rebuilding
under a new question; previously observed results are never relabeled.

No replay is dispatched before every original request digest is complete. The
final barrier alone advances to prepared/full-queued; an arm requires its next
genuine lease. Delivery time stays 900 seconds. Operational allowance is derived
from exact unit/chunk count, not another scientific attempt: 33 units need one
definition plus nine digest deliveries (max55 total operational leases under the
existing constructor/execution/retry formula).

The transport issuer accepts native standalone scope only from a server-derived
original panel unit under its current canonical lease and plan.
`native_standalone_source_transport_v1` binds allocation-only programme, original
statistics and source projection; all authority flags are false. Plain/matched/
legacy SOLO cannot borrow it. Eligibility matches role, context scope and horizon.

## Consequences

This is durable bounded preparation, not a persistent semantic cache, relaxed
risk/statistics, new scheduler or renewed scientific budget. Exact serialized
request bytes/hashes remain stable across fresh leases; PHP object identity is
not a wire equality assertion. Partial prefixes and stale leases cannot become
dispatch or qualification. Software preparation does not supply untouched data.
