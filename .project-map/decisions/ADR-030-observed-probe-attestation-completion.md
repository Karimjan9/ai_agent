# ADR-030 - One observed probe-attestation technical completion

## Context and authorization

On 2026-10-07 the user explicitly authorized one bounded technical completion
after G260's original probe-attestation failure. Outcomes were already computed
and may have been inspected; this is not an unobserved schema-refusal repair.
Renaming the same physical question as new discovery is also not permitted.

The original Python request/receipt used the stored council evaluation plan's
probe, while Laravel's evaluation manifest retained the earlier generic Academy
probe. Exact window/data/cost/row bounds agree, but experiment identity/hash
differs. The response gate correctly fails closed on the wrong expected owner.

## Decision

Keep the original gate strict. Bind the native plan's final outgoing request
first, then freeze that same expected probe in the immutable evaluation manifest
before source/release/request sealing, in singleton and batch paths.

Add one explicitly named observed-probe-attestation completion to the existing
Feedback owner, durable work, constructor and arbiter. It requires the original
technical assessment and drained terminal cohort, original compressed request
and release/artifact proofs, and the exact supported three-arm ownership
collision. The generic expected probe is derived from the original immutable
scope/plan rather than accepted from a mutable SQL projection alone.

The owner derives and locks the original lineage root, binds its immutable
identity into the signed resolution and propagates a global completion cap of
one. An existing completion anywhere in that root lineage exhausts the cap,
including a failed successor. New receipt IDs, labels, releases or further
source edits cannot renew it. Missing, completed or unrelated comparative
outcomes do not fit this narrow repair proof.

Root identity is ownership ancestry, not a claim that every earlier question
had identical vectors. The server follows and verifies its existing signed
work/receipt/plan/generation links. Earlier descriptor materializations remain
visible history. Exact question parity is required against the current failed
original cohort; generated model display names are not behavioral changes.

New original arms retain the same physical question, source vectors, controls,
member ablation, window, data, capital, costs and risk. Retuning is forbidden.
Old failed runs, cached outcomes, models, plans, source seals and feedback remain
unchanged. The server openly acknowledges observed producer outcomes; no new
independent sample, scientific novelty or replenished discovery budget is claimed.
Existing bounded operational leases remain distinct from this one cohort cap.

## Consequences and unchanged limits

The completed cohort must still produce new correctly attested original replay,
comparison and feedback through the same canonical owners. Merely registering
this completion does not settle old science or authorize execution. A second
failure remains terminal diagnostic history, not another completion allowance.

This policy grants no repair/causal/economic/inheritance credit, Mentor, Parent,
paper or live authority. Authorized untouched independent windows remain a
separate dependency; 2026 stays paper-only. There is no second scheduler,
post-hoc receipt substitution, weaker hash check or source hot-fix to an active
generation. Release follows admitted-work drain and loaded-source verification.

The signed completion also fences the generic screening-learning projection
before any derived write, including information/repair credit and provisional
Mentor/cartridge/posterior/selector projections. One idempotent lifecycle
diagnostic records the withholding; original native comparison and research
feedback remain durable knowledge. Valid ordinary discovery and independent
panel ownership keep their existing policies.
